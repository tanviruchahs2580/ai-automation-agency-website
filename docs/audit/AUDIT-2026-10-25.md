## 2. P0 — must be fixed before any public launch

### P0-1 · Six open dependency advisories, and CI's own security gate is **red on `main` today**

`npm audit --omit=dev --audit-level=high` — the literal command in `.github/workflows/ci.yml` — exits **1**. Installed `next@16.3.8` carries three advisories (GHSA-2464-fhr4-w9xw critical RCE, GHSA-p3m5-59mp-jv5r high DoS, GHSA-673q-mjm6-r5xr critical RCE); installed `zod@3.25.76` carries one high (GHSA-mrhx-c7xc-m3w5). `npm audit fix` resolves Next with a **minor** bump to 16.4.3.

**Precise reachability — do not overstate this.** I checked each vector against this configuration:

| Advisory | Reachable here? | Why |
|---|---|---|
| Next.js RCE via Image Optimization + SVG | **No** | No `next/image` usage anywhere, and `images.dangerouslyAllowSVG` is not set (no `images` key in `next.config.ts` at all). |
| Next.js DoS via Server Actions | **No** | Zero `"use server"` directives in `src/`; the three `action={` hits are a React-node prop on `Accordion`, not a form action. |
| Next.js RCE in `use cache` + typed arrays | **No** | Zero `use cache` directives. |
| Zod memory exhaustion on oversized collections | **No** | `projectBriefSchema` (`src/lib/validation.ts:52-68`) has no arrays, records or sets — only strings and enums. |

So there is **no live exploit today**. That is not reassurance; it is the finding. The repository is one feature away from every one of those vectors (adding a hero screenshot with `next/image` makes the critical RCE live), and the gate designed to catch that is currently failing. **Severity: high (governance), not critical (runtime).**

### P0-2 · Broken social sharing on 51 of 52 routes

`buildMetadata()` (`src/lib/seo.ts:84-92`) returns a page-level `openGraph` object, and Next.js **replaces** the accumulated `openGraph` at each metadata level rather than deep-merging it. The root-level `src/app/opengraph-image.tsx` asset is therefore discarded by the very next page-level `openGraph`.

Measured on the fresh build:

```
og:image present?   index: 2     about: 0   services: 0   insights: 0
                    technology: 0  start-a-project: 0   privacy: 0
```

Only `/` (whose `opengraph-image.tsx` shares its segment) and `_not-found` escape. Meanwhile `src/lib/seo.ts:94` declares `twitter: { card: "summary_large_image" }` on every page — a promise with no image behind it. Every LinkedIn/Slack/X share of the articles and case studies you most want shared renders as a bare text link. **This is the single highest-ROI fix in the report.**

### P0-3 · The primary CTA fails WCAG AA contrast — in both themes

`src/app/globals.css:918-954`. `.btn-primary` paints a *gradient background image* with `color: #fff` at `font-size: 0.875rem` (14px, weight 500 — not "large text", so the threshold is 4.5:1).

| Theme | Position | Composited | Ratio |
|---|---|---|---|
| Dark | top stop (`#5285ff` 88% + `#fff` 12%) | `rgb(103,148,255)` | **2.89:1** ❌ |
| Dark | vertical centre (where the label sits) | `rgb(74,127,251)` | **3.66:1** ❌ |
| Dark | bottom stop (`#2e6bf6`) | `rgb(46,107,246)` | 4.62:1 ✅ |
| Dark | hover top (`#5285ff`) | `rgb(82,133,255)` | **3.41:1** ❌ |
| Light | top (`#3b76f7`) | — | **4.10:1** ❌ |

This is every primary CTA on the site: header, hero, all fifteen `CtaSection` instances, both tools, the intake submit. It is invisible to the existing axe gate because **axe cannot evaluate gradient backgrounds** and reports them as "incomplete", not "violation". The project's own `src/lib/a11y-matrix.md:27` tests only the flat `#2e6bf6` stop, which is the one stop that passes.

### P0-4 · The primary conversion form is server-rendered **invisible**

`src/components/forms/ProjectIntake.tsx:476-480` applies `initial={{ opacity: 0, x: 24 }}` unconditionally on the server. The prerendered HTML proves it:

```
.next/server/app/start-a-project.html:
  <div aria-live="polite" class="mt-8 space-y-5" style="opacity:0;transform:translateX(24px)">
```

The entire wizard body — headings, fields, everything — is transparent until hydration completes and framer-motion runs the entrance. On a slow device, a throttled connection, or with JS blocked/partially failed, **the highest-intent page on the site looks empty.** Same class of defect at `src/components/scenes/ArchitectureLandscape.tsx:146`, confirmed in both `index.html` and `technology.html`:

```
id="architecture-layer-panel" style="opacity:0;transform:translateY(8px)"
```

This is a deviation from the repository's own house pattern — `Reveal`, `RevealStagger`, `HeroInstrument`, `CountUp` and `CookieConsent` all use a `requestAnimationFrame` gate that is SSR-safe. Two components opted out. `src/app/template.tsx` adds a third instance: `.route-fade` animates `opacity: 0 → 1` over 200ms, so the first painted frame of every page is transparent content.

Note the irony: the repo wrote `docs/qa/measure-reveal-flash.mjs` specifically to detect this bug class, but it samples only `h1.text-hero` on `/` — inside the *gate-protected* `Reveal` — so it structurally cannot see any of the three.

### P0-5 · The brand is a declared placeholder that collides with an existing vendor

`src/data/site.ts:3-8` states: *"PLACEHOLDER BRAND DATA… The brand/legal entity form and any real contact channels must be supplied before launch."* The name is nonetheless hardcoded as a live operating entity in 13+ non-test files (`src/lib/seo.ts:54`, `src/components/layout/Footer.tsx:65` — `© {year} VANTIQ SYSTEMS. All rights reserved.`, `src/app/privacy/page.tsx:8`, `src/app/feed.xml/route.ts:22`, `src/messages/en.json:4`).

**"Vantiq" is a real, operating enterprise AI vendor** (Vantiq, Inc., real-time AI orchestration) in the same market this site addresses. Shipping under an unmodified placeholder that collides with a competitor in-category is a trademark and credibility problem, not a copy nit. Compounding it: `src/lib/insights.ts:9` sets `author: "VANTIQ Systems Engineering Team" // PLACEHOLDER authorship` — and `src/lib/seo.ts:189` emits that team name as `"@type": "Person"`, telling search engines a human wrote the articles. The team page claims *"No ghost authors, no stock faces."*

All four legal surfaces (`/privacy`, `/terms`, `/cookie-policy`, plus `DraftBanner`) render a visible "Placeholder document — requires review by qualified legal counsel" warning. This is *disclosed* and *tracked* (`LAUNCH-CHECKLIST.md` §1 task 7) — which is why it is a launch blocker rather than a dishonesty finding — but it is a launch blocker.

## 3. P1 — fix before launch

**P1-1 · Form field boundaries fail WCAG 1.4.11 (3:1) in both themes.** Inputs are identified by a 1px border on a near-identical fill (`--color-line: rgba(244,242,236,0.09)` at `globals.css:62`). Measured: border-vs-fill **1.27:1** dark / **1.19:1** light; fill-vs-page **1.14:1** / **1.19:1**. Nothing else identifies the control until focus arrives.

**P1-2 · Heading hierarchy skips `h2` on five index routes.** `src/components/ui/Card.tsx:62,110,151` emit `h3` with nothing between them and the page `h1`: `/solutions` → `h1, h3×6, h2`; `/services` → `h1, h3×7, h2`; `/industries` → `h1, h3×12, h2`; `/work`, `/insights` likewise. The card grid *is* the page content, so heading-based navigation jumps from the title straight to the footer CTA. axe flags this as `heading-order` (moderate) — and `e2e/a11y.spec.ts:63-67` filters to `["serious","critical"]`, so **every moderate rule is invisible to CI**. `/technology` and `/about` do it correctly, so this is an inconsistency, not a constraint.

**P1-3 · Self-declared performance budget missed by 2.2×, unenforced, and the PASS table omits it.** `DESIGN-SYSTEM.md:189` sets **JS < 90 KB gzip**; measured `/` first-load is **193.8 KiB gz**. Framer Motion ships the *full* build (including `ProjectionNode`, `dragControls`, `LayoutGroup` — none of which the app uses) into the global baseline of **22 of 23 routes**: `29t-j_j9gq02r.js` = 39,385 B gz, paid by `/privacy`, `/terms` and `/cookie-policy` which contain no motion at all. `grep -rn "LazyMotion|domAnimation" src/` → **zero hits**. Separately, **zod ships to the browser** on `/start-a-project` purely to obtain four constant arrays (`src/components/forms/ProjectIntake.tsx:6-11` imports from `src/lib/validation.ts`, which builds schemas at module scope) — 20,934 B gz, the difference between the heaviest route and the norm. `RENOVATION-REPORT.md:144` reports a budget row reading "CSS ≤24KB, fonts ≤180KB, raster images=0 | **PASS**" — the one budget that is failing is absent from the row.

**P1-4 · A CSS cascade bug silently disables the editorial typeface site-wide.** `src/components/ui/Card.tsx:151` sets `className="h-card mt-3 font-editorial text-xl"`. But in `globals.css`, `.font-editorial` (line 331) and `.h-card` (line 362) are both **unlayered with equal specificity**, and `.h-card` comes later — so its `font-family: var(--font-display)` and `font-size: 1.06rem` win over both `.font-editorial` and Tailwind's layered `text-xl`. Insight card titles therefore render as sans-serif Geist at ~17px instead of Source Serif 4 at 20px. The fourth typeface of the brand, and the entire visual hierarchy between product cards and editorial cards, does not render. (Verified by cascade order, not only by screenshot.)

**P1-5 · The homepage hero makes the 8-second test fail.** `.text-hero` is `clamp(3rem, 7vw + 0.5rem, 6rem)` (`globals.css:701`) → **96px** at 1440 inside a ~690px column. The result is a 10-word sentence set **8 lines / ~780px deep** in a 900px viewport, with the object of the sentence ("…guesswork") off-screen and the **primary CTA ~300px below the fold**. The company's own positioning message is the first casualty.

**P1-6 · Governance gaps on a public repository.** No branch protection on `main` (`gh api` → 404). Dependabot **security** updates **disabled** (the `dependabot.yml` present handles version updates only). Secret scanning and push protection disabled. **No `LICENSE`** (`license: null`) on a public repo. No `SECURITY.md`, no `CODEOWNERS`, no issue/PR templates. Seven dependabot PRs open for up to two months (oldest 2026-08-26), including `zod 3→4` and `framer-motion 12→13`. Critically: CI's comment says *"This workflow guarantees that only code which passes lint, unit tests, a production build, type-checking and full cross-engine E2E is shipped"* — but CD is Vercel's GitHub integration, which deploys `main` **on push, not on CI success**. The guarantee as written is false.

**P1-7 · The intake rate limiter is keyed on a client-controllable header.** `src/app/api/project-brief/route.ts:34-37` reads `x-forwarded-for` and takes the **first** (leftmost) value — the position a client can supply. 5 requests/minute/IP is then bypassable by rotating a spoofed header. There is also **no request-body size cap**: `request.json()` parses unbounded JSON, and `cleanString` runs `.trim()` → regex replace → length refine, so a very large `problem` field is regex-scanned *before* its 4000-char limit is applied. `.env.example` documents the proxy requirement, which is to the authors' credit, but "deploy behind something that overwrites this header" is a deployment precondition, not an enforced control.

**P1-8 · The E2E gate is not green, and the failures cluster on the conversion path.** 58 passed / **3 failed** / 4 flaky / 12 skipped. All three failures are WebKit, and all three are the intake wizard and readiness tool:

```
[webkit] a11y.spec.ts:276  intake: invalid fields expose aria-invalid and a described error
[webkit] tools.spec.ts:73  project intake wizard submits end-to-end and shows reference ID
[webkit] tools.spec.ts:130 intake wizard blocks invalid step with inline errors
```

The readiness failure is `waiting for element to be visible, enabled and stable` on an option button — i.e. Playwright never considers the element settled, which points at a continuously-animating ancestor rather than a locator problem. Four nav/search tests are flaky on chromium and firefox. Even allowing for WebKit-on-Windows being a known-weak engine, a Microsoft-grade posture would either pin engines or fix the instability — right now the green CI badge overstates the safety net.

**P1-9 · Structured data is present but largely ineligible.** `articleJsonLd` (`src/lib/seo.ts:178-194`) omits `image` (required for Article rich results) and `publisher.logo` (required by Google), has no `dateModified`, and types a team as `Person`. `organizationJsonLd` (`:103-119`) has no `logo`, the one property Google requires — despite `icon.png`, `apple-icon.png` and `icon-512.png` all existing. `softwareJsonLd` (`:209`) sets `price: "0"` with no `priceCurrency` and no `aggregateRating`/`review`. There is also **no feed autodiscovery** (`alternates.types`) in `<head>`, so `/feed.xml` is reachable only via the footer link.

**P1-10 · This is a light-theme token bug the screenshots could not show.** `globals.css:145-146`:

```css
--color-muted: #374151;
--color-faint: #374151;   /* identical */
```

`faint` and `muted` are the **same colour** in light theme, so a two-level text hierarchy collapses to one level everywhere it is used (~30 call sites at 11–11.5px). In dark theme they are properly distinct (`#a3a9b4` vs `#7d8494`), and even there `faint`-on-`surface2` measures **4.60:1** — technically passing with zero headroom, on 11px text, while `a11y-matrix.md:66` claims that token is AA-safe "on all surface tokens".

## 5. P3 — low / polish

- `JsonLd` is exported from `src/components/ui/Accordion.tsx:28` — a structured-data injector living inside an accordion module, imported by the root layout. Code-organisation smell.
- Rate limiter is per-instance and in-memory; under Vercel's multi-instance serverless model the effective limit is `5 × instances`. Acknowledged in the header comment; still a real gap for a public form.
- `manifest.ts:11-12` hardcodes `#0a0b0e` for `theme_color`/`background_color` while `layout.tsx:27-30` correctly varies `theme-color` per colour scheme — a light-theme install gets a dark splash.
- Icons declare no `"purpose": "maskable"`.
- `feed.xml` `lastBuildDate` is request time, not content-change time (`feed.xml/route.ts:26`).
- Security headers are a solid set (HSTS+preload, `X-Frame-Options: DENY`, `nosniff`, Referrer-Policy, Permissions-Policy, `poweredByHeader: false`) but omit `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`, and CSP is **Report-Only**. - `contactRole` is the one personal-data field missing an `autocomplete` token (`organization-title`).
- Search dialog has no visible close control below 640px (the only hint is an `aria-hidden` `ESC` keycap); new-tab links carry no visual/SR cue.
- `BeforeAfter.tsx:66` applies `transition-opacity` while toggling *colour* classes, so the intended crossfade never runs.
- Layout-property animations that could be compositor-only: Navbar height 96→64px on scroll (`Navbar.tsx:178-182`), `ReadingProgress` width, `.service-row-grid` on `grid-template-rows`. Mouse-move handlers in `Spotlight.tsx:19-27` call `matchMedia` twice plus `getBoundingClientRect()` per event with no rAF.
- Duplicate font binaries ship under four URLs (`inter-tight-400` ≡ `inter-tight-500`, `jetbrains-mono-400` ≡ `jetbrains-mono-500`; identical md5s) — up to ~74.5 KB of redundant transfer. No `unicode-range`, no `preload`.
- `articleJsonLd` and `organizationJsonLd` ergonomics; `/work/*` reference architectures have no structured type at all.
- `error.tsx:34` puts `role="alert"` on the whole 500 panel including the "Try Again" button — assertive regions should carry a status, not interactive content.

## 6. What is genuinely excellent (stated precisely, so the critique is calibrated)

This is not a mediocre codebase with a long defect list. Several things here are better than most commercial sites I would audit:

1. **The honesty layer is the best asset on the site, and it is real.** "Example architecture — not a client engagement", "Illustrative model outputs — not client results", "Readiness labels, not certificates", "Capability statements, not certifications", and an explicit refusal to claim SOC 2 / ISO / HIPAA until verifiable. **No fabricated client names, logos, testimonials, awards, team bios, or outcome metrics exist anywhere in the data layer** — and the test suite actively enforces this. For an agency site, that restraint is rare and strategically correct.
2. **No secrets have ever been committed.** `.env.*` is gitignored with `!.env.example`; a full `rev-list --all` scan for key patterns returns nothing.
3. **The backend is genuinely careful for its size.** Zod validation server-side with dash normalisation for API integrations, client-side errors wired to fields via `aria-describedby`/`aria-invalid`, honeypot, bounded-memory rate limiter with an expiry sweep (a detail most implementations miss), a `not-configured` → `receipt-only` email path that **never blocks the visitor's receipt**, and a deliberate decision to never log brief content.
4. **XSS handling of JSON-LD is correct.** `Accordion.tsx:28-38` escapes `<` → `\u003c` before injection. Most sites get this wrong.
5. **SEO fundamentals are excellent apart from the social image.** 51/51 unique titles, 51/51 unique descriptions, 51/51 canonicals; the sitemap covers **100%** of routable pages with `lastModified` emitted only where a real date exists (better than most); valid RSS 2.0 with correct escaping, `Content-Type` and absolute URLs; correct `robots.txt`; correct `noindex` on 404.
