# DECISIONS — ARKYON rebrand

| # | Decision | Rationale / trade-off | Status |
|---|---|---|---|
| D-01 | Storage keys renamed to `arkyon-*` / `arkyon:*` with a **legacy read-fallback on access** (theme, consent, recent searches, intake draft). Mechanics, stated precisely: reads check the new key first, then the legacy key; **writes always go to the new key only; legacy values are never migrated forward or deleted** — they keep working as a permanent read fallback. The exit-intent "seen" flag is sessionStorage and session-scoped, so it was renamed **without** a fallback (worst case: the prompt may show once more next session). | A bare rename silently resets every returning visitor's consent choice — that is a consent regression (prompt: consent decision + persistence must be preserved). The read-fallback preserves decisions while removing active brand strings from user-visible state handling. | APPROVED (autonomous scope) |
| D-02 | `window.__vantiqAnalytics` provider hook renamed to `window.__arkyonAnalytics` **without** alias shim. | No provider is wired today (verified); the hook has zero external consumers; a shim would keep dead brand surface. Event names and consent gate unchanged. | APPROVED |
| D-03 | Brand default in `src/data/site.ts` becomes `ARKYON` (no suffix). `NEXT_PUBLIC_BRAND_NAME` override retained for ops flexibility but its default flips. `deriveBrandForms` keeps API shape so tests change minimally. | Prompt §0.1 exact-name rule; keep deployment override behaviour intact. | APPROVED |
| D-04 | DOM id `vantiq-grid` → `arkyon-grid`; e2e/comment references updated together. | Past duplicate-id defect history — single definition kept. | APPROVED |
| D-05 | Branch `feat/arkyon-rebrand-frontend-v3` off `27b566c`; owner's Button.tsx line-ending-only change left uncommitted and untouched. | Phase 0 rule: pin base, protect owner work. | APPROVED |
| D-06 | No new runtime dependencies for the rebrand (SVG logo hand-authored; `next/og` reused). framer-motion major upgrade NOT included (dependabot branch exists upstream — separate owner decision). | Prompt: no incidental major upgrades. | APPROVED |
| D-07 | URLs unchanged (all 51 paths stable); no redirects needed; only visual/brand/copy changes. | Prompt §8.1 default: preserve URLs. | APPROVED |
| D-08 | Independent review: no human reviewer is available in this session. Plan: separate adversarial sub-agent review passes (visual, standards via code-review skill, specification) + explicit `INDEPENDENT REVIEW: BLOCKED/NOT VERIFIED` label in release report. | Prompt §2 independence rule: sub-agent ≠ independent, must be labelled honestly. | APPROVED |
| D-09 | Push/PR/merge/production deploy: NOT executed autonomously. All work committed locally on the feature branch; owner approval requested at handover. | Global SOP gates pushing/merging/deploying; prompt §1.1 same. | APPROVED |
| D-10 | The `brainstorming` skill was not invoked as a Q&A loop: the V3 master prompt is itself the complete creative brief and explicitly forbids pausing for owner re-statement; its Phase 2 performs the structured direction exploration instead. | User instruction: execute all actions without pausing. | RECORDED |
| D-11 | Historical code comments that describe past defects keep the names they describe (e.g. the `vantiq-grid` id history in `GridLines.tsx`, `check-rendered-html.mjs`): they are dated records of what the code used to do, not active identity. Active identifiers and all user-facing strings use the new brand. | Rewriting history comments would falsify the record; the brand tests scan comments out anyway. | APPROVED |
| D-12 | Legacy storage-key fallbacks are written to be **permanently safe to remove** in a later release once the pre-rename visitor cohort declines; removal is a one-line-per-module change recorded here. They remain in rendered HTML only inside the pre-paint script's fallback read (verified: the only `vantiq` occurrences in built HTML). | Balance between visitor-state preservation and brand-string hygiene. | RECORDED (owner may direct removal) |
| D-13 | Contrast ratios are **not** quoted in CSS comments or docs as authoritative numbers — comments state direction + which test computes them; `contrast.test.ts` is the single source of the ratios. | Prose numbers go stale (standards review F3 found ~0.5–1.0 drift in first-draft comments); the test parses the shipped stylesheet. | APPROVED |
| D-14 | `/ai-readiness` SoftwareApplication JSON-LD name keeps the baseline construction `${shortName} AI Readiness Assessment` → "ARKYON AI Readiness Assessment". Spec review flagged the "ARKYON AI" substring as borderline vs the no-suffix rule; ruled NOT a lockup form (it is brand + tool title, as "VANTIQ AI Readiness Assessment" was at base), and the string is asserted by e2e — changing it is copy churn without a rule breach. | Avoid churn in a tested surface for a non-violation; owner may reorder later. | RECORDED |
| D-15 | Two additive scope items from the independent design critique were accepted beyond strict rebrand scope: (1) a contextual hero CTA on work detail ("Discuss This Architecture" — the only page family without an in-hero next step), (2) mobile compaction of the consent banner (P1 finding). Both disclosed in ROUTE-FEATURE-COVERAGE.md. | Design-review P1/P2 findings; additive, honest, behaviour-preserving. | APPROVED |
